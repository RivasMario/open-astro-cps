## 1. Executive Overview: What Is Motorola CPS?

Motorola **CPS (Customer Programming Software)** is the graphical configuration suite used to read, edit, and write the personality codeplug of Motorola two-way radios.

Historically, Motorola radios underwent three architectural software generations:
1. **DOS RSS (Radio Service Software)** (1980s–late 1990s):
   - Targeted Saber, Astro Saber, Spectra, Astro Spectra, HT1000, Maxtrac.
   - Ran in 16-bit real mode DOS. Directly manipulated memory registers via a Hardware Interface Box (RIB - Radio Interface Box).
2. **ASTRO CPS (Windows 16/32-bit)** (Late 1990s–early 2000s):
   - Targeted original ASTRO radios (XTS 3000, Astro Saber, Astro Spectra).
   - Built on 16/32-bit Windows C++/MFC. Stored codeplugs as raw memory image archives.
3. **ASTRO 25 CPS (Cedar Platform)** (2002–2018):
   - Targeted XTS 5000, XTS 2500, XTS 1500, MT1500, PR1500, XTL 5000, XTL 2500, PM1500.
   - Built with Microsoft Visual C++ 6.0 / MFC, using an underlying **Microsoft Jet / Access Database Engine** container inside `.cpg` files.
   - Communicated with radios using the **SB9600 / ASTRO Serial Bus protocol**.

## 2. The Anatomy of an ASTRO Codeplug (`.cpg` File)

### 2.1 The Container Format
An official `.cpg` file generated by ASTRO 25 CPS is an **OLE Compound Document (Structured Storage)** file:
- If opened in a hex editor, it begins with the standard Microsoft Compound File Binary (CFB) header:
  `D0 CF 11 E0 A1 B1 1A E1`
- Inside this compound container resides a set of structured streams:
  - **`Codeplug`**: The serialized binary data structures.
  - **`RadioInfo`**: Radio model number, serial number, flashcode, firmware version, and codeplug version.
  - **`Summary`**: File metadata, author, last modified timestamp.
  - **Jet Database Stream**: Embedded tables defining relations between personalities, scan lists, systems, and controls.

### 2.2 The Relational Model: Pointers over Direct Storage
The biggest surprise for engineers coming from amateur radio software (like CHIRP) is that **Motorola codeplugs do not store channels inside zones**. 

Motorola designed their architecture in the 1990s to conserve precious EEPROM space (64 KB to 128 KB total). They normalized the data like a relational database:

```
+─────────────────────────────────────────────────────────────────────────────+
|                         MOTOROLA CODEPLUG RELATIONAL GRAPH                   |
+─────────────────────────────────────────────────────────────────────────────+

   +----------------------+
   |  ZONE CHANNEL TABLE  |
   | (Physical Knob Map)  |
   +----------+-----------+
              |
              | Points to Personality ID
              v
   +------------------------------------+          +---------------------------+
   |   CONVENTIONAL PERSONALITY TABLE   | -------> |      SCAN LIST TABLE      |
   | • Rx Freq: 851.5125 MHz            |          | • Member 1: Personality 1 |
   | • Tx Freq: 851.5125 MHz            |          | • Member 2: Personality 2 |
   | • Squelch Type: CSQ / PL / DPL     |          | • Priority 1 Channel      |
   | • Power Level: High / Low          |          +---------------------------+
   | • Tx Inhibit: True / False         |
   +------------------+-----------------+
                      |
                      | Points to System ID
                      v
   +------------------------------------+          +---------------------------+
   |        ASTRO SYSTEM TABLE          | -------> |     CRYPTO KEY TABLE      |
   | • Rx NAC: $293                     |          | • Key 1: TEAM_ADP_1       |
   | • Tx NAC: $293                     |          | • Algorithm: ADP (0xAA)   |
   | • Talkgroup ID: 1                  |          | • Key Value: A1B2C3D4E5   |
   | • Voice Mode: ASTRO (P25)          |          +---------------------------+
   +------------------------------------+
```

#### Why This Matters for OpenAstro:
- In CHIRP: Channel 1 has a frequency, a name, a CTCSS tone, and a power setting.
- In Motorola: Zone 1, Channel 1 is simply an entry that says: *“Point to Conventional Personality #4, with Display Name ‘DISPATCH’, using Scan List #1.”*
- **OpenAstro's Job:** Provide a flat, human-friendly spreadsheet format (CSV / JSON) and handle the relational pointer generation under the hood automatically.

## 3. The Physical Hardware & Wire Protocol

### 3.1 Connector & Electrical Layer
Motorola ASTRO 25 portable radios (XTS 2500, XTS 5000, PRC-153) expose their programming interface via the side universal accessory connector:
- **XTS 5000:** Standard 13-pin side Hirose connector.
- **XTS 2500 / PRC-153:** 10-pin side universal connector.
- **Signals:**
  - `GND`: Ground.
  - `VCC_OUT`: 5V or 7.5V battery rail.
  - `CTS_IN` / `BOOT_CTRL`: Mode selection and hardware flow control.
  - `TXD`: Serial data from radio to PC.
  - `RXD`: Serial data from PC to radio.
  - `OPT_SEL` / `ONE_WIRE`: Factory programming detection pin.

### 3.2 The Serial Transport: SB9600 & ASTRO Bus
Motorola uses an adaptation of the **SB9600 (Smart Bus 9600)** protocol:
- **Default Baud Rate:** 19,200 baud (early Astro radios used 9,600 baud; high-speed flash uses 38,400 or 115,200 baud).
- **Parameters:** 8 Data Bits, No Parity, 1 Stop Bit (8-N-1).

#### Packet Structure:
```
[0x05] [LENGTH] [OPCODE] [PAYLOAD ...] [CHECKSUM]
```
1. **`0x05` (START_BYTE):** Frame synchronization byte.
2. **`LENGTH` (1 byte):** Length of `[OPCODE] + [PAYLOAD]`.
3. **`OPCODE` (1 byte):** The command or response identifier.
4. **`PAYLOAD` (Variable):** Arguments, memory addresses, or read/write bytes.
5. **`CHECKSUM` (1 byte):** 8-bit two's complement sum:
   $$\text{Checksum} = (-\sum_{i=1}^{N} \text{Byte}_i) \pmod{256}$$

## 4. Reverse-Engineered Opcode Reference Table

| Opcode (Hex) | Direction | Command Name | Description |
| :---: | :---: | :--- | :--- |
| `0x00` | PC $\rightarrow$ Radio | **`RADIO_PING`** | Tests link presence. Radio responds with `0x00` ACK. |
| `0x01` | Radio $\rightarrow$ PC | **`RADIO_ACK`** | Link acknowledgement. |
| `0x02` | Radio $\rightarrow$ PC | **`RADIO_NACK`** | Packet rejected / bad checksum. |
| `0x10` | PC $\rightarrow$ Radio | **`ENTER_PROGRAMMING_MODE`** | Commands radio CPU to mute RF, display `"PROGRAMMING"`, and enter flash loop. |
| `0x11` | PC $\rightarrow$ Radio | **`EXIT_PROGRAMMING_MODE`** | Commands radio to reboot into normal mission mode. |
| `0x14` | PC $\rightarrow$ Radio | **`GET_RADIO_INFO`** | Requests Serial Number, Model Number, Flashcode, and Firmware Version. |
| `0x15` | Radio $\rightarrow$ PC | **`RADIO_INFO_REPLY`** | Returns hardware strings (e.g., `H46KDH9PW7BN`, `500008-000488-4`). |
| `0x20` | PC $\rightarrow$ Radio | **`READ_MEMORY_BLOCK`** | Payload: `[ADDR_HI] [ADDR_MID] [ADDR_LO] [BYTE_COUNT]`. |
| `0x21` | Radio $\rightarrow$ PC | **`READ_MEMORY_REPLY`** | Payload: `[STATUS] [DATA...]`. |
| `0x30` | PC $\rightarrow$ Radio | **`WRITE_MEMORY_BLOCK`** | Payload: `[ADDR_HI] [ADDR_MID] [ADDR_LO] [BYTE_COUNT] [DATA...]`. |
| `0x31` | Radio $\rightarrow$ PC | **`WRITE_MEMORY_REPLY`**| `0x00` = Success, `0x01` = Write Protected, `0x02` = Checksum Error. |
| `0x3F` | PC $\rightarrow$ Radio | **`DSP_PEEK`** | Factory debug: reads DSP internal memory register directly. |
| `0x40` | PC $\rightarrow$ Radio | **`DSP_POKE`** | Factory debug: writes DSP internal memory register. |

## 5. The Radio Memory Map: Partitions & Boundaries

The memory on an ASTRO 25 radio (Freescale ColdFire architecture) is partitioned into distinct flash blocks:

```
0x0000_0000 ┌─────────────────────────────────────────┐
            │ HARDWARE BOOTLOADER                     │  READ-ONLY
0x0000_4000 ├─────────────────────────────────────────┤
            │ TUNING PARTITION ("Soft-Pots")          │  CRITICAL FACTORY RF CALIBRATION
            │ • Crystal Oscillator Reference Frequency│  * MUST NEVER BE OVERWRITTEN *
            │ • RF Power Output Curve Tables          │  (Corrupted = Brick / ERROR 01/82)
            │ • Receiver Front-End Tracking Filters   │
0x0000_8000 ├─────────────────────────────────────────┤
            │ HOST FIRMWARE / HOST OPERATING SYSTEM   │  READ-ONLY (Flash Upgrades)
0x0010_0000 ├─────────────────────────────────────────┤
            │ DSP FIRMWARE (Vocoder & Modulation)     │  READ-ONLY (Flash Upgrades)
0x0020_0000 ├─────────────────────────────────────────┤
            │ CODEPLUG STORAGE AREA (EEPROM / Flash)  │  MUTABLE BY CPS
            │ • Radio Serial & Flashcode Header       │
            │ • Zone & Channel Tables                 │
            │ • Conventional Personalities            │
            │ • ASTRO Digital Systems & Tones         │
            │ • Crypto Keys (ADP Software Keys)       │
0x0024_0000 └─────────────────────────────────────────┘
```

### Safety Rule for OpenAstro:
`open-astro-cps` must enforce a **Hardware Address Boundary Interlock**:
- Memory writes are strictly bounded between `0x0020_0000` and `0x0023_FFFF`.
- Any serial command attempting to write to `0x0000_4000 – 0x0000_7FFF` (Tuning) must be aborted immediately.

## 6. The Three Artificial Paywalls (And How OpenAstro Eliminates Them)

### 6.1 The Flashcode Bitmask
- A Flashcode is a 13-character string: e.g., `500008-000488-4`.
- It decomposes into individual feature bits:
  - Byte 0, Bit 0: Conventional Analog
  - Byte 0, Bit 3: P25 Digital Conventional Operation (+$800)
  - Byte 1, Bit 2: SMARTNET / SmartZone Trunking (+$1,200)
  - Byte 2, Bit 1: Software Encryption (Motorola ADP) (+$400)
  - Byte 2, Bit 7: Front Panel Programming (FPP) (+$500)
- **OpenAstro Advantage:** When generating or modifying configurations, OpenAstro does not artificially hide menus or require payment to configure features the radio hardware supports.

### 6.2 Advanced System Keys (ASK) & Trunking Gates
- Motorola CPS requires an **Advanced System Key (ASK)**—a physical Dallas Semiconductor iButton cryptographic hardware dongle—to program trunked system IDs (`System ID: $293`, `WACN: BEE00`).
- Without the dongle, official CPS refuses to save trunked talkgroups, locking public safety agencies into proprietary vendor contracts.
- **OpenAstro Advantage:** Software-based, clean-room parsing. Allows authorized agency technicians to configure system profiles using standard JSON without dongles or registry hacks.

### 6.3 Out-of-Band Frequency Validation
- Official CPS blocks entering frequencies outside the factory bandsplit (e.g. 144.390 MHz Ham APRS in a 150–174 MHz commercial VHF radio).
- In official CPS, this check is implemented in the client GUI DLLs (`A25*.dll`) via simple range checks.
- **OpenAstro Advantage:** The radio’s internal Voltage-Controlled Oscillator (VCO) can physically lock and transmit clean RF up to ±5–8 MHz beyond factory specs. OpenAstro bypasses the artificial GUI block and programs ham frequencies directly.
